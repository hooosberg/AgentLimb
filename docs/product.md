# 产品目标与交互原则

> 这份文档是判断「该不该做某个功能」的唯一标准。写代码前先读它；
> 与它冲突的需求，先改这份文档再改代码。

## 一句话定位

**给任意支持 MCP 的智能体软件，装上一双能操作浏览器的眼睛和手；侧栏是它和你说话的地方。**

对标物：Claude in Chrome（Claude Code 的浏览器控制扩展）。目标不是"功能差不多"，
而是**交互效率与心智模型完全对齐**，同时去掉对特定 AI 品牌的绑定。

## 三个核心承诺

### 1. 复制提示词即可完成首次浏览器接入

用户点击「复制连接提示词」本身就是授权动作：扩展打开一个 30 分钟的**接入窗口**，窗口内第一个连上来的未知 AI 自动受信，之后永久记住。没有确认页、没有弹窗、没有需要填进配置的配对码。

这条链路上刻意不做三件事：

1. **不做确认页**。旧版的「XX 希望连接浏览器 / 允许 / 忽略」页是多余的：用户点复制已经表达过意图，再点一次允许只是把同一个意图确认两遍。整页已删除（`ui/pairing/`）。
2. **不把授权写进配置**。授权状态只存在扩展的私有存储里（`agentlimb.onboardUntil` + `agentlimb.pairedClients`）。一旦写进 MCP 配置的 env，窗口过期就会留下一个永远失效的死码，用户只能改配置重启才能修——这是最坏的失败形态。
3. **不做超时等待**。窗口不在有效期内时，扩展当场回一句「未授权」，宿主把它翻译成可执行错误：让用户点一次复制再重试。不改配置、不重启、不重装。

一次复制只授权一个 AI。窗口外或窗口已用完时，侧栏会显示「有一个 AI 想接入，但还没获授权」，点一下复制即可放行——已经连着的那一个会立刻受信，不用等它重连。

这不会替代智能体软件自身的 MCP Trust/Enable。用户需按该软件实际要求启用 MCP；本产品不猜测各客户端的具体授权界面。成功必须由当前智能体会话的 AgentLimb `ping` 与 `tabs_context` 确认，随后先 `say` 告知侧栏，再在 AI 对话明确告诉用户可以直接提出任务。相同身份后续自动重连，不再需要窗口。

**提示词固定为英文**，界面语言只影响扩展 UI。中英混杂会让 AI 对同一件事读到两套指令，得不偿失。

提示词的第一关是**安装源定位**。浏览器不给扩展自己的磁盘路径：`runtime.getURL()` 只给 `chrome-extension://<id>/`，`getPackageDirectoryEntry()` 只给包内相对路径，`management.getSelf()` 没有 path。但 ID 本身可以反查出目录，分两步：

1. **问 Chrome**：每个 profile 的 `Secure Preferences` 里记着 `extensions.settings[<id>].path`。一条 Node 命令遍历各平台 profile 目录，0.3 秒出结果，不用扫盘。
2. **扫描兜底**：profile 位置异常或换了 Chromium 系浏览器时，`find bin/agentlimb.mjs` 后按 `SHA-256(绝对路径) → 前 16 字节 → 0-f 映射 a-p` 过滤，只留哈希等于该 ID 的目录。

指纹能区分「同一份代码的备份与拷贝」，而 `package.json` 规则不能——两个相同副本都满足 name=agentlimb。所以顺序是：先读 profile，再扫盘，都没有才问人。

用户若在「设置 → 高级 → 安装源目录」存过路径，该路径会写进提示词作为候选，但仍要求它哈希到同一个 ID（防止指向副本）。

这条规则来自一次真实失败：AI 在本机只找到旧的 `.agentlimb.backup-*` 目录，又被告知不能从旧 runtime 取文件，于是卡在第一关不动。

### 2. 侧栏状态清楚、只显示当前记录

| 状态 | 唯一责任 | 不做什么 |
|---|---|---|
| 未连接 | 复制连接提示词 | 不显示进度、不显示教程、不显示标签列表 |
| 已连接 | 与当前 MCP 智能体对话 | 不放快捷操作按钮（截图/标签/读页面都由自然语言和工具完成） |

状态栏有四种状态：未连接、已连接、正在操作、等待回复。优先级为未连接 > 正在操作 > 等待回复 > 已连接。页面工具调用期间显示正在操作，等待最终回复时显示等待回复。

扩展可同时与 `BRIDGE_PORTS` 中最多六个 MCP 宿主建立 SSE 连接，并分别保留每个 AI 的信任。
只有 `connectedClientId` 指定的当前 controller 能执行浏览器任务；侧栏的聊天记录与草稿按 AI
隔离。已配对但离线的 AI 显示为已保存配对，不会因断线或退出而撤销信任。

**当前决策：多 AI 信任保留，单 controller 串行控制。** 打开另一个已信任的 AI 不会自动抢控制；
用户可在管理器中选择在线 AI。显式切换仅在当前任务空闲时成功，忙碌时返回 busy，不强制中断。
经一次复制窗口授权的新 AI 会在当前空闲时接管；若当前 AI 正在执行任务，新 AI 会等待任务完成后再接手。
由 MCP 工具 `ping` 发起的检查不抢占 controller。

侧栏**与运行完全无关**：关掉侧栏，AI 照样能新建标签、读页面、点击输入。
这一条必须在 UI 上明说（离线提示和在线状态标题提示各一句），否则用户会以为必须一直开着。

### 3. 已配对侧栏 = 智能体的聊天窗，而且默认看得见你眼前的页面

这是本产品与"普通 MCP 浏览器工具"的分水岭：

- 用户问「这个页面讲什么 / 帮我翻译一下 / 这个按钮能点吗」时，**不需要截图、不需要报标签**。
  侧栏发出的每条消息都自动携带当前标签页的上下文：
  - **一张当前标签的截图**（JPEG，压缩到 ~165KB 以内）
  - `url` / `title`
  - 可见文本摘录（默认 2500 字）
  - 可交互元素及其 ref（默认 30 个，ref 可直接用于 `computer` / `form_input`）
- 智能体收到就能直接回答，**零额外往返**；需要更多细节它自己再调 `read_page`。
- 智能体的回复通过 `say` 工具回到侧栏聊天流里 —— 所以这是一次真正的对话，
  不是单向的"下指令"。
- 侧栏最多保存最近 20 条用户、智能体和系统记录；记录只保留消息文本、时间，以及可选的页面标题、URL 和不可读标记。不会保存截图、页面正文或交互 refs，也不会把这些记录重放给 AI。
- 浏览器工具活动只通过一个实时「正在操作」状态提示，不形成活动历史。任务完成后智能体必须调用 `say` 给出最终回复；`say` 仅用于最终回复，不用于进度播报。断开或重连会清除等待与操作状态。
- 多标签场景：用户自己说「这 4 个标签分别是什么」，智能体用 `tabs_context` 去看；
  但**默认永远是当前标签**，不需要用户先点按钮声明"我要问这个页面"。

### 聊天是发件箱，不是对话——这是产品规则，不是实现细节

侧栏无法替 agent 开启一轮对话：消息只能搭在 agent 的下一次工具结果上送达。所以：

- **侧栏发消息 ≡ 在 agent 自己的聊天框里打字**。语义一样：排队、等它下次动作时读到、
  它回 `say` 你就看到回复。它空闲时你发的消息会等——这是正常的，不是坏了。
- **输入永远可打。** 只有「这一条正在发」的瞬间会禁用；没有回复、工具在跑，都不禁用。
- **每个等待都有期限**：回复 60 秒、停止确认 20 秒。到期就解锁并留一条系统说明，
  绝不让用户面对一个永远转圈的输入框。
- **不要承诺"即时回复"。** 文案说「消息已送到，AI 下次操作时会看到」，不说「等待 AI 回复」然后卡住。

这条规则的理由：聊天是次要的，效率是主要的。一个卡死的聊天框会让用户以为整个插件挂了。

## 交互原则（决定"要不要加一个 UI 元素"时用）

1. **默认观察当前页面，而不是让用户描述页面。** 任何要求用户先"截图/选标签/读页面"的设计都是错的。
2. **不抢焦点。** AI 的工作标签一律后台打开（`active:false`）；用户在看视频、在别的标签打字都不受影响。
3. **不打扰，但可见。** 用户不需要盯着侧栏，操作期间用单一状态清楚提示。
4. **页面操作保持可见。** 页面里有幽灵光标与辉光边框；侧栏不保存或展开逐步活动日志。
5. **聊天记录只用于回看。** 它不是 AI 上下文或操作日志。
6. **文案通用化。** 任何用户可见文本都不出现第三方品牌名（有测试断言把守）。
7. **停止是一次明确的对话请求。** 右侧按钮空闲时显示「发送」；正在操作或等待回复时显示「停止」。停止只发送普通用户消息「用户请求停止当前任务：请停止后续浏览器操作，并用 say 回复确认。」不取消宿主任务、不撤销配对，也不收集页面截图或上下文。发出后按钮进入「已请求停止，等待 AI 确认…」，输入保持禁用；收到最终 `say` 回复后才清除停止请求及操作/等待状态。断开或重连也清除该状态。

## 断开、移除与停止

「停止」是聊天消息，不是协议取消：它使用既有 `user_message` 帧，请智能体停止后续浏览器操作并通过 `say` 确认。它不保证宿主中正在执行的动作会被强制中断。

连接断开、宿主退出或临时掉线都只将该 AI 标为离线，保留它的信任。设置里的「移除」会撤销所选 AI
的信任，不影响其他已配对客户端。停止仍是协作消息，不撤销配对，也不强制终止宿主任务。

## 控制权归属（谁占聊天窗）

多个 AI 同时在线时，聊天窗永远只属于一个 AI。规则按「谁先表达了意图」排序：

| 发生什么 | 结果 | 为什么 |
| --- | --- | --- |
| 别的 AI 发来任务（工具调用），当前空闲 | **自动切到它** | 用户正在用 A，突然要 B 干活，B 一开口就该是 B 的窗口 |
| 已受信的 AI 只是重连/启动 | **不抢窗**，回到「在线待命」 | 后台软件自动重启不该打断用户手上的对话 |
| 用户刚点了「复制连接提示词」并完成首次授权 | **切到它** | 用户刚为这个 AI 做了动作，意图明确 |
| 当前 AI 正忙（工具在跑 / 等回复 / 正在发送） | **谁都不抢**，排队到当前任务 `say` 结束 | 半路换人会让两个 AI 互相踩 |
| 当前 AI 断开 | 优先切回上次用的在线 AI，否则切到任一在线 AI | 聊天窗不该停在一个已经不在的 AI 上 |

排队中的调用带宿主 deadline：等到控制权时如果已过期，**拒绝并且绝不执行**（迟到的浏览器操作比
失败更危险）。`ping` 不抢控制权。用户也可以在左上角管理器里手动切换，忙时会被拒绝而不是强切。

## 侧栏设置

未连接与已连接共用**同一条顶部栏**，位置不随状态跳动：左侧是当前 AI 与状态（未连接 / 已连接 /
正在操作 / 等待回复），点开即轻量管理器；右侧固定两个入口——复制连接提示词、齿轮设置。

左侧那一行要能回答「现在谁在操作、还有谁在线」：有别的软件在线时追加「另有 N 个在线」，
不必展开管理器才知道。管理器的每行状态分四种：正在使用 / 等待接手 / 待命 / 已保存配对·离线
（绿点=在线，黄点=等待接手，灰点=离线）。

管理器是顶栏下方的浮层，不占主区：列出全部已配对 AI 及其状态（正在使用 / 等待接手 / 待命 / 已保存离线），
在线且非当前的可一键切换，底部「连接其他 AI」直接复制提示词，「管理」进入完整列表。

齿轮设置采用栏目式导航：首页是分组列表（连接 / 通用 / 关于），点进子页，返回键逐级退回。
- **连接其他 AI**：为第二个 AI 客户端复制独立提示词，并说明新 AI 连上后会接管聊天窗口。
- **已连接的 AI**：完整列表，显示已连接数量，可切换当前在线客户端或单独移除其信任。
- **界面语言**：自动、简体中文、English，选择持久化保存；只影响扩展界面，复制出的连接提示词固定英文。
- **高级**：安装源目录（写进复制出的提示词，AI 靠它找到安装包）与 MCP 命令路径。
- **关于**：版本、简介、GitHub / 官网 / 许可链接。

新 AI 接管、旧 AI 切回都不需要重新配对：信任按 clientId 保留，聊天记录与草稿按 AI 隔离。

## 明确不做

- ❌ 「第几步/共几步」的进度条（旧版的性能包袱，拖慢执行）
- ❌ 侧栏快捷操作按钮（截图 / 标签列表 / 读取页面）——默认上下文已经覆盖
- ❌ `stop_agent` 协议帧或强制取消宿主任务；停止按钮只发送普通 `user_message`
- ❌ 让用户在确认页给 agent 起名字——软件自己会报名字（`initialize.clientInfo.name`），确认页也已整体删除
- ❌ 依赖某个特定 AI 的专有协议——只走标准 MCP
- ❌ 连接提示词里出现中文或中英双语分支——只发英文一份
- ❌ 让 AI 自己"找找看安装包在哪"——必须给可执行的定位命令与校验判据
- ❌ 云端中转——全部本地回环（127.0.0.1）

## 效率对照（vs Claude in Chrome）

| 环节 | 我们怎么做 |
|---|---|
| 传输 | 本地 SSE 推送 + POST 回传，无轮询 |
| CDP 会话 | 持久 attach，按 tab 去重，不每次动作重连 |
| 内容脚本 | `document_start` 常驻，a11y 树随取随用，不按需注入 |
| 后台标签 | `Emulation.setFocusEmulationEnabled`，后台可点可输入 |
| 多步动作 | `browser_batch` 一次往返最多 20 步 |
| 截图 | 自适应 JPEG（base64 预算内自动降质） |
| 上下文 | 侧栏消息自带页面文本 + refs，省掉 `tabs_context` + `read_page` 两次往返 |
| 回复 | `say` 直接写进侧栏聊天流 |

## 验收标准（可测）

`node scripts/live-test.mjs` 验证浏览器工具、聊天门控与断线重连（真 Chrome + 真 MCP 客户端，断言数以运行报告为准）。

1. 授权后重启智能体：**不弹任何页面**，直接可用。
2. 侧栏关掉时，AI 仍能新建后台标签并读页面；用户当前标签不变。
3. 侧栏发「这个页面讲什么」：AI 不需要 `tabs_context` / `read_page` 就能答（消息里已有上下文）。
4. AI 的回复出现在侧栏聊天流里（`say`），重开侧栏仍可查看最近 20 条记录；历史记录不会重放给 AI。
5. 页面采集/发送或消息尚未收到回复时显示「等待回复」；浏览器工具开始后显示「正在操作」，在工具阶段之间持续保持，直到 `say` 最终回复回到「已连接」。发送失败保留草稿。
6. 折叠线以下的元素：`computer{action:'click', selector}` 能点中（自动滚动）。
7. React/Vue 受控输入：`form_input` 后框架 state 同步变化。
8. 页面里能看见幽灵光标与辉光边框；页面本身没有任何可点控件。
9. 关闭侧栏 / 关闭 Chrome / 重启智能体，都不需要重新配对。
10. chrome:// / 扩展页这类读不到正文的页面：消息里明说「Chrome 不允许读取或控制」，
    不能装作空白页。
11. 十几步操作期间侧栏只显示「正在操作」，不产生逐步历史；任务完成后必须有 `say` 最终回复。
12. 新建标签只把本次新开的标签自动加入该窗口橙色 AgentLimb 分组；后续调用复用该组，默认仍在后台打开。
13. 正在操作或等待回复时，按钮显示「停止」；点击后发送固定停止请求，不附带页面截图/上下文，输入保持禁用并显示「已请求停止，等待 AI 确认…」，直到 `say` 最终回复清除状态。停止请求只表达用户意图，不声称强制取消宿主流程。
14. 连接断开或重连时清除操作/等待/停止请求状态，但保留该身份的信任；设置中移除某 AI 只撤销该 AI 的信任，其他配对保持不变。
15. 点击「复制连接提示词」就是授权动作：它打开一个 30 分钟接入窗口（一次复制只授权一个 AI），提示词里**不含任何码**，也不需要粘贴到任何配置。窗口内的首次连接自动受信；窗口外得到「未授权 + 请用户点一次复制」的可执行错误，不出现确认页、不改配置、不重启。用户只需在真实智能体软件要求时完成该软件自身的 Trust/Enable。
16. 当前会话的 `ping` 与 `tabs_context` 都成功后，先通过 `say` 在侧栏反馈配对成功，再在 AI 对话说明可直接提出任务；成功后不再要求用户重复重启、授权或新开会话。若工具不可用，明确说明当前会话未启用 MCP，并只提出有证据支持的必要动作。
17. **配对速度**：桥接起来到浏览器完成授权 < 1000 ms；已有一个 AI 在线时启动第二个 AI 也能在 1 秒级被发现；一次复制只授权一个 AI；授权消息丢失会重连重试而不是显示假的「已连接」。这些由 `tests/pairing-speed.test.mjs` 断言，实测分布见 `npm run bench`。

## 迭代优先级

- P0：多客户端配对与持久信任、单 controller 与任务锁、16 工具、后台标签控制、侧栏四态、按 AI 隔离的最近 20 条记录和草稿、`say` 最终回复、页面上下文
- P1：AI 回复流式、多标签上下文一次带入
- P2：跨域 iframe、标签栏沙漏指示（运行中旋转）、会话导出
- P3：Web Store 上架、`npx` 分发
