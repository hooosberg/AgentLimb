# 产品目标与交互原则

> 这份文档是判断「该不该做某个功能」的唯一标准。写代码前先读它；
> 与它冲突的需求，先改这份文档再改代码。

## 一句话定位

**给任意支持 MCP 的智能体软件，装上一双能操作浏览器的眼睛和手；侧栏是它和你说话的地方。**

对标物：Claude in Chrome（Claude Code 的浏览器控制扩展）。目标不是"功能差不多"，
而是**交互效率与心智模型完全对齐**，同时去掉对特定 AI 品牌的绑定。

## 三个核心承诺

### 1. 配对 = 给 AI 装了一个 MCP

用户复制一段提示词粘给智能体 → 智能体自己配好 MCP → 浏览器弹一次配对页 → 点允许。
**此后永远自动**：智能体每次启动都会重新拉起 MCP 进程，扩展必须自己找回信任，
不能再弹配对页（这是最容易写错的地方，见 `docs/development.md` 已知坑）。

### 2. 侧栏有两个状态，各自只有一个责任

| 状态 | 唯一责任 | 不做什么 |
|---|---|---|
| 未配对 | 复制连接提示词 | 不显示进度、不显示教程、不显示标签列表 |
| 已配对 | 与智能体对话 | 不放"快捷操作"按钮（截图/标签/读页面都是多余的） |

**一个浏览器只认一个 AI（单租户）**：换软件（A → B）时，B 确认配对后 A 的信任自动失效，
侧栏顶部永远只有一行「正在与 <软件名> 驱动浏览器」，不会堆成历史列表。
同一条规则在扩展存储、宿主注册表、侧栏渲染三处都成立。

侧栏**与运行完全无关**：关掉侧栏，AI 照样能新建标签、读页面、点击输入。
这一条必须在 UI 上明说（未配对态和已配对态各一句），否则用户会以为必须一直开着。

### 3. 已配对侧栏 = 智能体的聊天窗，而且默认看得见你眼前的页面

这是本产品与"普通 MCP 浏览器工具"的分水岭：

- 用户问「这个页面讲什么 / 帮我翻译一下 / 这个按钮能点吗」时，**不需要截图、不需要报标签**。
  侧栏发出的每条消息都自动携带当前标签页的上下文：
  - **一张当前标签的截图**（JPEG，压缩到 ~165KB 以内）
  - `url` / `title`
  - 可见文本摘录（默认 2500 字）
  - 可交互元素及其 ref（默认 30 个，ref 可直接用于 `computer` / `form_input`）
- 智能体收到就能直接回答，**零额外往返**；需要更多细节它自己再调 `read_page`。
- 智能体的回复通过 `say` 工具回到侧栏聊天流里 —— 所以这是一次真正的对话，
  不是单向的"下指令"。
- 多标签场景：用户自己说「这 4 个标签分别是什么」，智能体用 `tabs_context` 去看；
  但**默认永远是当前标签**，不需要用户先点按钮声明"我要问这个页面"。

## 交互原则（决定"要不要加一个 UI 元素"时用）

1. **默认观察当前页面，而不是让用户描述页面。** 任何要求用户先"截图/选标签/读页面"的设计都是错的。
2. **不抢焦点。** AI 的工作标签一律后台打开（`active:false`）；用户在看视频、在别的标签打字都不受影响。
3. **不打扰，但可见。** 用户不需要盯着侧栏，但侧栏里能看见 AI 在干什么（见下条）。
4. **操作可见、可停。** 页面里有幽灵光标 + 辉光边框 + 「停止智能体」按钮（紧急刹车就在
   页面上，不占侧栏）；侧栏只留「断开」，其余全是聊天。
5. **聊天瀑布兼作操作日志。** AI 每次动浏览器，聊天流里出现一行浅色小字
   （`· 读取页面结构` / `· 新建标签 → https://…`）。一物多用，不额外占 UI。
   如果将来觉得吵，可以折叠，但默认保留——用户需要知道"它到底动了没"。
6. **文案通用化。** 任何用户可见文本都不出现第三方品牌名（有测试断言把守）。

## 明确不做

- ❌ 「第几步/共几步」的进度条（旧版的性能包袱，拖慢执行）
- ❌ 侧栏快捷操作按钮（截图 / 标签列表 / 读取页面）——默认上下文已经覆盖
- ❌ 让用户在配对页给 agent 起名字——软件自己会报名字（`initialize.clientInfo.name`）
- ❌ 依赖某个特定 AI 的专有协议——只走标准 MCP
- ❌ 云端中转——全部本地回环（127.0.0.1）

## 效率对照（vs Claude in Chrome）

| 环节 | 我们怎么做 |
|---|---|
| 传输 | 本地 SSE 推送 + POST 回传，无轮询 |
| CDP 会话 | 持久 attach，按 tab 去重，不每次动作重连 |
| 内容脚本 | `document_start` 常驻，a11y 树随取随用，不按需注入 |
| 后台标签 | `Emulation.setFocusEmulationEnabled`，后台可点可输入 |
| 多步动作 | `browser_batch` 一次往返最多 20 步 |
| 截图 | 自适应 JPEG（base64 预算内自动降质） |
| 上下文 | 侧栏消息自带页面文本 + refs，省掉 `tabs_context` + `read_page` 两次往返 |
| 回复 | `say` 直接写进侧栏聊天流 |

## 验收标准（可测）

1. 配对后重启智能体：**不弹配对页**，直接可用。
2. 侧栏关掉时，AI 仍能新建后台标签并读页面；用户当前标签不变。
3. 侧栏发「这个页面讲什么」：AI 不需要 `tabs_context` / `read_page` 就能答（消息里已有上下文）。
4. AI 的回复出现在侧栏聊天流里（`say`），并且重开侧栏仍在（会话持久化）。
5. 点「发送」后立刻出现「**正在思考…」动画；AI 回话即消失；40 秒没回应则换成人话
   提示，不无限转圈。
6. 折叠线以下的元素：`computer{action:'click', selector}` 能点中（自动滚动）。
7. React/Vue 受控输入：`form_input` 后框架 state 同步变化。
8. 页面里能看见幽灵光标与辉光边框；点「停止」后 AI 立即停手。
9. 关闭侧栏 / 关闭 Chrome / 重启智能体，都不需要重新配对。

## 迭代优先级

- P0（已完成）：配对、持久信任、15+1 工具、后台标签控制、侧栏双态、`say` 回显、页面上下文
- P1：AI 回复流式（`say` 多次输出）、操作日志可折叠、多标签上下文一次带入
- P2：跨域 iframe、标签栏沙漏指示（运行中旋转）、会话导出
- P3：Web Store 上架、`npx` 分发
